# Document Architecture

## Purpose

This document establishes the structural hierarchy, operational relationships, and developmental authority governing the three core design files of the Noctis Civilization Module:

- `VISION.md`
- `ART_DIRECTION.md`
- `NOCTIS_ECOLOGICAL_ENGINE.md`

It serves as a meta-framework to guide future AI and human expansion, ensuring that no technical feature, visual asset, or system mechanic breaks the core conceptual loop.

---

## 1. The Tri-Document Hierarchy

The design architecture operates on a strict top-down mandate. Each document holds supreme authority over its respective layer. Changes in a lower-tier document **cannot** violate the boundaries set by the tier above it.

```
+------------------------------------+
|             VISION.md              |  <-- Tier 1: Absolute Conceptual Anchor
+------------------------------------+
                  |
                  v
+------------------------------------+
|          ART_DIRECTION.md          |  <-- Tier 2: Aesthetic & Spatial Interface
+------------------------------------+
                  |
                  v
+------------------------------------+
|    NOCTIS_ECOLOGICAL_ENGINE.md     |  <-- Tier 3: Mechanical & Biological Execution
+------------------------------------+
```

### Tier 1: `VISION.md` — The Constitutional Anchor

| Field | Definition |
|-------|------------|
| **Authority** | Absolute sovereign over purpose, philosophy, and user psychology |
| **Core mandate** | Ensures the module never behaves like a traditional, high-distraction game. Protects the Study OS-first paradigm. The civilization remains an interpretive, persistent reflection of real-world productivity |
| **Conflict resolution** | If a mechanical feature or art style makes the application distracting, stressful, or overly game-like, it violates `VISION.md` and is **discarded** |

### Tier 2: `ART_DIRECTION.md` — The Aesthetic Interface

| Field | Definition |
|-------|------------|
| **Authority** | Sovereign over visual formatting, scale, perspective, layout composition, and environmental mood |
| **Core mandate** | Translates the abstract philosophical light of `VISION.md` into tangible 2D/2.5D visual parameters. Dictates how the user views the world through a clean, Fluent-inspired Windows workspace layout without shattering the living diorama illusion |
| **Conflict resolution** | Any visual design proposing full-3D assets, free-orbit cameras, or intrusive UI overlays that obscure study tools violates `ART_DIRECTION.md` and is **blocked** |

### Tier 3: `NOCTIS_ECOLOGICAL_ENGINE.md` — The Functional Blueprint

| Field | Definition |
|-------|------------|
| **Authority** | Sovereign over biological physics, citizen anatomy, technological evolution, and algorithmic transmutation formulas |
| **Core mandate** | Implements the concrete systems that fulfill the conceptual promises of Tier 1 and Tier 2. Provides rigorous scientific constraints — modeled on real-world abyssal and cave-dwelling biology — that dictate how the simulation calculates growth |
| **Conflict resolution** | If a feature introduces standard surface elements (traditional daylight, vocal speech, fire-based metallurgy), it violates `NOCTIS_ECOLOGICAL_ENGINE.md` and must be **fundamentally redesigned** |

## 2. Cross-Document Cross-Pollination

The three documents form a symbiotic feedback loop. A single high-level directive must translate consistently across all tiers.

| Architectural component | Tier 1: `VISION.md` | Tier 2: `ART_DIRECTION.md` | Tier 3: `NOCTIS_ECOLOGICAL_ENGINE.md` |
|-------------------------|---------------------|----------------------------|---------------------------------------|
| **Light** | Poetic translation layer for knowledge; tracks long-term learning progress | Precious, localized glow pooling softly against deep nocturnal fields | Physical, metabolic bio-nutrient synthesized via chemiluminescent Luciferin loops |
| **Technology** | Evolution of how the city asks questions and records history | Visual language shifts from pulsing spore-hearth glow to restrained bio-circuit networks | Operates through non-visual tactile knots, crystal light-guides, and optogenetic circuit maps |
| **Environment** | Inner world shaped directly by specialized user effort | Layered 2D silhouettes depicting dense, organic structures breathing in the night | Actively mutates using exact biological schemas (mycelial roots vs crystalline lattices) |

## 3. Automated Generative Guardrails for AI Engines

When a generative AI model creates a new feature (e.g., *"Design a library for language students"*), it **must** consult this validation protocol **sequentially**:

### Step 1 — Check Tier 1 (`VISION.md`)

> Does this library turn into a micromanaged mobile-game building requiring active clicking?

- **If yes:** HALT. It must remain a passive, symbolic reflection of study.
- **If no:** Proceed to Step 2.

### Step 2 — Check Tier 2 (`ART_DIRECTION.md`)

> Is this building rendered as a standalone 3D asset or cluttered with game-like labels?

- **If yes:** HALT. It must be a 2.5D illustrated plate that natively fits inside a clean application window pane.
- **If no:** Proceed to Step 3.

### Step 3 — Check Tier 3 (`NOCTIS_ECOLOGICAL_ENGINE.md`)

> Does the library use paper books, combustion lamps, or Noctae-facing flat screens?

- **If yes:** HALT. Citizens read via tactile lateral-line sliding on fiber scrolls under cold bioluminescent lantern organs. The building must be structurally anchored into a chemosynthetic fungal node powered by focus minutes.
- **Human-facing exception:** The Study OS interface itself may use normal readable text, labels, and Fluent UI. This rule applies to diegetic in-world assets only.
- **If no:** Feature may proceed to detailed design.

## 5. Canonical Terminology Locks

These terms are reconciled across all tiers. Do not reintroduce deprecated or contradictory language.

| Term | Meaning | Never means |
|------|---------|-------------|
| **Spore-hearth** | Cold bioluminescent civic light organ; communal glow without combustion | Fire, forge, ember, smoke, or industrial heat |
| **Warm-colored glow** | Human-facing visual hue (amber, gold, orange motes) | Thermal warmth, combustion, or daylight brightness |
| **Study OS UI** | Human-facing calendar, notes, dashboard, labels, and overlays | Diegetic Noctae tool, in-world flat screen, or strategy HUD |
| **Deep-sea / cave analogs** | Biological and architectural inspiration for dark-adapted systems | Literal underwater gameplay, cave simulator, or 3D exploration |
| **Scroll / tablet (in-world)** | Tactile fiber scroll or raised inscription surface read by lateral-line touch | Paper book, e-ink screen, or daylight-readable diegetic text |
| **Light / bio-light** | Metabolic energy from focus minutes; chemiluminescent or bioluminescent | Coins, XP, score currency, or guilt-based punishment |
