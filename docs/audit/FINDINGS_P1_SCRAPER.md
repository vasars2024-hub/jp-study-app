## What resolution these ask for

Per `jp-dispatch` §6 and `honesty-probe` §6 this run **documented and did not fix anything**.
For the record, A–E rows here resolve as *disable + label honestly + a known-issues row*, and the
F rows as *relocate/polish/hide*:

- `P1-B1`, `P1-B2` — the only honest options are to read the real free space or to delete the
  claim. A storage warning whose threshold is invented is worse than no warning: on this host it
  would stay silent through a queue ten times larger than the disk.
- `P1-B4`, `P1-D1` — ship no starter schedules, or ship disabled ones with a target the user must
  fill in. Separately, a run that could not fetch its configured target must say so rather than
  quietly answering from the catalogue instead.
- `P1-E4` — 34 controls need an inert marker, or removal. `set.browser`'s deletion
  (`featureStatus.ts:46-53`) is the precedent this repo already set, and it is the better one.
- `P1-F2` — the Torrents tab is real work that a default-configuration user never reaches;
  *promote*, not *hide*.

**`KNOWN_ISSUES.md` still does not exist** (`git ls-files | rg -i known_issues` → no output,
re-checked this run). Per `honesty-probe` §6 its location is the user's call, so no file was
created.
