## What resolution these ask for

Per `jp-dispatch` §6 and `honesty-probe` §6 this run **documented and did not fix anything.**

- `P7-F1`, `P7-F2`, `P7-F3` — the four unconverted files need the standard `useT()` pass plus
  `ja`/`zh`/`ru` entries; `node tools/i18n-check.cjs` will not catch them, because it compares
  catalogs against each other and these strings never entered a catalog. **That is the more
  important finding than any individual string:** the project's i18n gate is structurally unable
  to see a file that never adopted `t()` at all.
- `P7-D1` — render the existing `grammar.examples.tatoebaCredit` key (or a `dict.` sibling) in
  `DictionaryResults`' examples block. The string, its four translations and the link already
  exist; this is a render site, not new work.
- `P7-B2` — the branch guard at `apkgImport.ts:106` should test for *resolved models*, not for a
  non-empty string. `readNotes` is not exported and has no unit test; `modelsFromNormalizedRows`
  is tested (`apkgParse.test.ts:99-111`) but the branch **selection** never is.
- `P7-F5` — a census correction, owned by `docs/audit/`, not by the app.
- `P7-A2`, `P7-A3`, `P7-A4` — remain unmeasured by design. Measuring them needs a disposable Anki
  profile on a non-default port, which is the user's call to set up.

**`KNOWN_ISSUES.md` still does not exist** (`git ls-files | rg -i known_issues` → no output,
re-checked this run). Per `honesty-probe` §6 its location is the user's call, so no file was
created.
